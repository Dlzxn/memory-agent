# memory-agent

Консольный ассистент на GigaChat с долгой памятью. Из обычного разговора он запоминает факты о пользователе и о людях, которых тот упоминает, не дублирует их, отличает прямые утверждения от догадок и обновляет устаревшее.

> Статус: MVP в разработке.

```
──────────────────────────────────────────────────
  Ассистент с долгой памятью
  /help — команды, /exit — выход
──────────────────────────────────────────────────

Вы: меня зовут Лёша, я пишу на Python
Ассистент: Приятно познакомиться, Лёша! ...

Вы: мой друг Вася любит Go
Ассистент: ...

Вы: /memory
О тебе:
  • зовут Лёша
  • пишет на Python
Вася:
  • любит Go
```

## Зачем

Это переработка памяти агента с хакатона «AI-импульс 2.0». В первой версии было три проблемы:

1. **Слабое подтверждение фактов.** Уверенность росла от числа повторений, поэтому повторённая ошибка становилась «правдой».
2. **Дубли.** Один и тот же факт, сказанный разными словами или на другом языке, сохранялся дважды.
3. **Атрибуция.** Факты о других людях из разговора приписывались пользователю.

Как каждая из них решается, описано в разделе «Ключевые решения».

## Стек

- Python 3.14, менеджер зависимостей [uv](https://docs.astral.sh/uv/)
- [langchain-gigachat](https://github.com/ai-forever/langchain-gigachat): модель `GigaChat-3-Lightning`
- LangChain `create_agent` (LangGraph под капотом): цикл «модель → вызов инструмента → модель»
- JSON-файл как хранилище памяти
- numpy: появится вместе с эмбеддингами


## Как это работает

1. `Dialog` читает строку пользователя. Если это команда (`/memory`, `/clear` и т. п.), обрабатывает её сам.
2. Иначе передаёт текст в `Agent.call()`. Агент добавляет сообщение в историю и вызывает LangChain-агента.
3. Модель сама решает, вызвать ли инструмент: сохранить факт, поискать в памяти, обновить или удалить.
4. Инструменты работают с `JsonStore` и возвращают модели короткий JSON со статусом.
5. Финальный ответ модели выводится в консоль, а полная история (вместе с вызовами инструментов) остаётся в `Agent.dialog`.

## Хранилище

`src/data/data.json` — список фактов:

```json
{
  "id": "f_305a2406",
  "subject": "user",
  "fact": "пишет на Python",
  "source": "stated",
  "priority": 2,
  "confirmations": 1
}
```

| Поле | Значение |
|---|---|
| `id` | `f_` + 8 hex-символов из uuid4 |
| `subject` | о ком факт: `"user"` или имя другого человека |
| `fact` | короткая формулировка без имени субъекта |
| `source` | `"stated"`: человек сказал это прямо; `"inferred"`: догадка модели |
| `priority` | `1` ключевое (имя, город, работа), `2` навыки и интересы, `3` мелочи |
| `confirmations` | сколько раз факт подтвердился |

`JsonStore` пишет атомарно: сначала во временный файл, потом `os.replace`. Если программа упадёт посреди записи, файл останется целым.

## Инструменты агента

| Функция | Что делает |
|---|---|
| `save_fact(subject, fact, source, priority)` | Сохраняет факт. Если такой уже есть у этого `subject`, не создаёт дубль, а увеличивает `confirmations`. Повторное прямое утверждение превращает догадку в `stated` |
| `search_memory(query, subject="user")` | Ищет факты о человеке по словам запроса (длиннее 2 символов). Сортирует по `priority`, затем по `confirmations`, возвращает до 10 штук. Пустой запрос возвращает все факты |
| `update_fact(fact_id, new_fact)` | Заменяет устаревший факт и сбрасывает `confirmations` в 1 |
| `forget_fact(fact_id)` | Удаляет факт по просьбе пользователя |

Описания инструментов для модели берутся из докстрингов (`@tool(parse_docstring=True)`), поэтому докстринг здесь и есть промпт.

## Ключевые решения

- **Атрибуция.** У каждого факта есть `subject`. Факты о других людях сохраняются под их именем.
- **Догадки отдельно.** `source="inferred"` помечает предположения модели. В `/memory` они показаны как «(догадка)», а прямое подтверждение переводит их в `stated`.
- **Противоречия.** Новый факт, который противоречит старому («переехал в Москву» после «живу в Нижнем»), обновляет запись через `update_fact`, а не добавляется рядом.
- **Дедупликация.** Сейчас сравнивается нормализованный текст (регистр и пробелы). Следующий шаг: косинусная близость эмбеддингов, чтобы «пишу на Python» и «I code in Python» склеивались.
- **Модель видит только нужное.** Инструменты возвращают урезанную запись (`_short`), без служебных полей.

## Команды чата

| Команда | Действие |
|---|---|
| `/help` | список команд |
| `/memory` | что агент помнит, сгруппировано по людям |
| `/clear` | очистить историю диалога; долгая память остаётся |
| `/exit`, `exit`, `выход`, Ctrl+C | выйти |

## Запуск

1. Установить зависимости:

   ```bash
   uv sync
   ```

2. Создать `.env` в корне проекта с ключом авторизации GigaChat (его выдают в [личном кабинете разработчика](https://developers.sber.ru/studio)):

   ```
   Authorization_Key=...
   ```

3. Запустить из корня проекта. Корень нужен в `PYTHONPATH`, потому что `memory_func.py` импортирует `src.database.store`:

   ```powershell
   # PowerShell
   $env:PYTHONPATH = "."; uv run python src/main.py
   ```

   ```bash
   # bash
   PYTHONPATH=. uv run python src/main.py
   ```

   В PyCharm достаточно запустить `src/main.py`: корень проекта уже в путях.

## Evals (план)

`evals.jsonl`: 10–15 сценариев. Для каждого проверяется, какие функции вызваны и что оказалось в памяти.

| Сценарий | Ожидание |
|---|---|
| «я пишу на Python», затем «I code in Python» | один факт, `confirmations = 2` |
| «мой друг Вася любит Go» | факт с `subject = "Вася"`, не про пользователя |
| «живу в Нижнем», затем «переехал в Москву» | факт обновлён, а не добавлен второй |
| несколько сообщений спустя «где я живу?» | ответ из памяти, верный |
| «забудь, где я живу» | факт удалён |
| «привет» | ни одного вызова функций |
| «кажется, ты любишь котов» (догадка) | `source = "inferred"` или не сохранено |

Цель MVP: проходят 80%+ сценариев, а причины провалов понятны.
